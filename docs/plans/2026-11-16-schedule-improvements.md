# 排期优化 Implementation Plan

**目标**：让作者打开排期就能判断今天先处理哪篇、哪些稿件需要补齐、哪篇已经实际发表。保留现有周历、拖拽、手动发布标记和排版入口。

**审查范围**：e90ed8c3405e3a7bbc16aaac6a818bbe8ee2c7f0 之后至 f89b617 的提交。现有排期实施记录见 [排期模块实施计划](2026-11-16-schedule-module.md)。本文件是后续开发计划。

## 现状与优先级

当前待排区解决「有哪些稿可以排」，周历解决「排在哪天」，顶部卡片提供排版、封面和已发标记入口。结构适合个人运营，建议保留。问题在于顶部卡片同时承担逾期处理和近期预告，已发状态也混合了计划时间与实际发表时间。稿件多时，需要能分开处理这些信息。

| 优先级 | 当前问题及依据 | 建议 |
| --- | --- | --- |
| P0 | 顶部卡片隔 30 秒更新，父级周历只在自身重渲染时读取时间。跨过排期时刻或午夜时，两处可显示不同状态。见 `client/schedule.jsx` 的 `NextUp`、`ScheduleView`。 | 共用时钟和排期日期规则。 |
| P0 | 已发卡片优先显示计划时间，浏览历史周时页头仍写「本周已发」。补录时界面没有实际发表时间输入，接口默认记为操作当下。见 `pubSlot`、`PublishedCard`、`articles/publish`。 | 分清计划、实际发表、标记时间，分开计算统计与卡片归属。 |
| P0 | 「导入复盘数据后会自动对上这篇」超出了实际能力。复盘目前按规范化标题唯一匹配，改过标题或有重名时不一定命中。重复发布标记还会覆盖时间。见 `src/insights.js` 的 `autoMatch` 和 `src/host.js` 的发布路由。 | 提示仅报告已标记，发布写入幂等，时间更正有明确入口。 |
| P1 | 最早逾期稿一直占据顶部，未来最近一篇被遮住。周历有稿时当天没有「排一篇」入口，卡片也堆了多个相同操作。 | 分开今天和待确认队列，日列始终保留新增。 |
| P1 | 待排区没有搜索，选稿列表也全量展示。窄窗会把待排区堆在日历前面；表单弹窗的 `aria-modal` 本身没有焦点约束。 | 增加搜索和就绪筛选，窄窗优先议程，完善键盘操作。 |

## 设计方案

推荐以「今日待办 + 周历」为默认。宽窗左侧保留待排区，右侧先显示今天的行动，再显示周历。窄窗用按日期排序的议程，待排区可按需展开。布局方案可以先用现有组件实现，后续再按实际稿量扩展。

- 只整理周历最省改动，但跨周遗留和今天的任务仍要在日历里找。
- 今日待办加周历能同时覆盖当天执行和一周规划，保留拖拽形成的习惯。
- 月历适合预先规划大主题，但每日编辑动作承载空间少。等实际出现频繁跨月安排，再决定是否增加月视图。

建议宽窗结构：

    排期                     上一周  回到本周  下一周
    待排 12 | 就绪 4          今天 2 篇    待确认 3 篇
    搜索稿件                 下一篇 · 周三 20:00
    待排卡片                 周一  周二  周三  周四  周五  周六  周日

「待确认」用于过点但尚未记录的稿件，列表保留实际已发、改期、取消三个动作。今天和待确认可以同时出现，逾期稿不会遮住下一篇。有当天任务时，下一篇可以缩成一行。默认显示一到两条待办，其余按数量展开。每列显示当天稿件和一个「＋」，时间碰撞只提示已有安排，允许同一时刻安排多篇。改到当前周之外时，成功提示显示具体日期并提供「查看当周」，保留用户主动决定是否跳转。

## 任务 1：统一时间与周范围（P0）

**文件**：`client/schedule.jsx`、新增 `src/schedule-time.js` 或项目同级纯函数模块、`test/schedule.test.js`。

1. 由 `ScheduleView` 提供一个当前时间，顶部、日历和议程统一读取。每 30 秒更新，窗口重新可见时立即校准。用同一个时间戳判断「已到点」的边界。
2. 周视图用所选周的日期键做状态。跨午夜或跨周时，「回到本周」以当前时间重新计算，正在浏览的历史周保持所选日期，不能随周偏移自动移动。
3. 建议排期保持浏览器本地时区作为兼容默认，明确展示时区标签。不要直接把已有数据全部切换成北京时间。保存采用带明确时区的 ISO 时间，服务端拒绝仅日期、无时区、非法或被自动归一化的时间。客户机和 Host 的年份边界判断要使用一致口径。
4. 保留拖拽改期时原时分，组件按目标日历日期构造时间。拖完清理高亮，包括落到空白区域和子元素之间移动的情况。

**验收**：模拟排期前后、午夜、周日到周一、跨年及带夏令时环境。倒计时、过点状态、日列日期和历史周导航一致。执行 `node --test test/schedule.test.js`。

## 任务 2：理清发布记录（P0）

**文件**：`src/article.js`、`src/host.js`、`client/schedule.jsx`、`test/schedule.test.js`。

1. 保留 `scheduledFor` 作为计划时间，`publishedAt` 存作者确认的实际发表时间。新增可选 `publishMarkedAt` 保存操作时刻。发布对话框默认实际时间为现在，可补记过去，禁止把未来时间作为实际发表时间。已有记录有多少信息便显示多少，不能推断历史补记的真实日期。改期、发布、撤销的归档校验统一在写入时执行。
2. 保留现有的计划日卡片归属，已发卡片标明实际发表时间，跨日时展示两者。没有计划时间的稿按实际发表日展示。周头使用「所选周计划内已发」描述按卡片归属计算的数量。若后续需要实际发表周统计，单独按实际发表日计算，避免混用。
3. 所有「标记已发」入口打开同一个对话框。重复确认已发时保留原时间，提供单独的「更正发表时间」。撤销后若原排期仍在则回到原日，未排期稿回待排。请求中锁住同一卡片动作，服务端用同一写入事务校验状态，测试并发标记。
4. 反馈使用「已记录发表时间」，复盘匹配仍按现有逻辑验证。除非另开任务修改匹配规则，否则不把发布标记描述为绑定文章数据。

**验收**：跨日补记、未排期发表、重复点击、撤销、归档、查看历史周和同名复盘数据。旧记录和原排期都能继续读。执行 `node --test test/schedule.test.js`。

## 任务 3：今天、待确认与周历（P1）

**文件**：`client/schedule.jsx`、`client/styles.css`。组件变多时拆到独立文件，继续复用卡片和操作回调。

1. 从同一份数据派生「今天待发」「过点待确认」「下一篇」。过点项按日期分组并可展开。点「定位」定位到对应周和卡片。顶部实际复用排版、下载和发布入口，逾期稿可直接改期或取消。
2. 卡片首行仅放时间、标题、状态。就绪环保留，并允许查看未完成项目。主操作按状态提供，其他动作收进菜单。与现有五项体检口径保持一致，未就绪作为提示，不阻断有意安排或补记。
3. 每日日头保留「排一篇」。合并已发与待发后的排序按其展示在日历上的时间计算。保留拖拽的快捷排期和表单路径。窄窗按天显示议程，待排区默认折叠，键盘用户可全程用按钮操作。
4. 初次无稿、无排期、筛选无结果及过点队列为空分别给适当入口，避免出现「稿件都排上了」这类与实际不符的文案。

**验收**：用一周含 10 篇稿、含两篇跨周逾期和同一天多篇的示例数据检查。能同时看到未来最近一篇和待确认数量，已占用日仍可新增。桌面与窄窗检查长标题、滚动、空态、拖拽及回到本周。

## 任务 4：待排检索和表单可用性（P1）

**文件**：`client/schedule.jsx`、`client/styles.css`，更新 `README.md` 和构建产物 `dist/client.js`。

1. 待排区提供标题搜索与「全部／就绪」筛选，保留最近编辑顺序及筛选后数量。选稿弹窗支持同样的搜索，输入可定位结果；当当前选择被归档或变为已排时，及时清除失效选择并给明确提示。
2. 参考项目已有原生 `dialog` 实现处理焦点约束、关闭恢复焦点、Escape、键盘选项导航；组合框提供独立可访问名称。保存中避免重复提交，失败保留输入。已选时段及拖拽默认时间可见。
3. 执行 `npm test`、`npm run build`、`git diff --check`。在浏览器完整走一遍「搜索待排 → 排期 → 改期 → 去排版 → 补记已发 → 撤销」，增加两次快速点击、请求失败和切换窗口尺寸场景。用 mock 验收应用内流程即可。

建议实施顺序为任务 1、2，再做任务 3、4。跨周规划需求稳定后再评估月历、重复排期和提醒，首轮先让每天的操作完整且可验证。
