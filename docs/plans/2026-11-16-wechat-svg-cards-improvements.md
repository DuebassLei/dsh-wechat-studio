# 公众号 SVG 动画卡优化 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让候选插入位置、数据来源、稿面预览和最终复制结果一致，并补齐键盘操作。

**Architecture:** 保留已内置的 wechat-svg-cards 和现有 Python 渲染器。修正候选状态与服务端校验，统一单卡和全文的渲染选项，再验证浏览器播放与公众号粘贴。

**Tech Stack:** React、Node.js、Python 3、SMIL、Node test、Chromium。

## 审查基线

原计划见 [动画卡开发计划](2026-11-16-wechat-svg-cards.md)。审查时 SVG 实现在暂存区，基于 `3479229`，现有 128 项测试全部通过。接手先用 `git status --short` 和 `git log -5 --oneline` 确认原实现是否已经提交。下面的优化基于现有八种卡片、原位预览、单卡复制和全文复制。

## 任务 1 · 固定候选的插入位置（高优先）

**文件**：`client/svg-cards.jsx`、`client/state.js`、`src/svg-cards.js`、`test/svg-cards-routes.test.js`。

1. 在浏览器复现：选 A 段生成卡片，随后把「插入到段落后」切到 B，直接插入。当前表单显示 B，但实际请求使用旧候选里的 A。先记录这个用例，并用延迟模型响应复现分析期间修改目标时的行为。
2. 候选区显示实际绑定的段号和正文摘录。位置或卡型改变后保留已编辑候选，明确标记为与当前选择不同。该状态下禁用插入，提供「恢复原选择」和「按当前选择重新生成」。目标被删除时清理表单里的失效 ID，避免原生下拉显示了首项但内部还保留旧值。
3. Host 调模型前捕获目标文本和哈希，整个请求使用同一份快照做提示词、数值校验和返回值。模型返回后确认目标仍存在且文本一致。当前代码保存的是 Store 对象的引用，等待模型期间正文可能原地被改写，导致用旧文生成却签上新文哈希。保留插入时在写入锁内的最终哈希检查。
4. 结束后用 `node --test test/svg-cards-routes.test.js` 验证。浏览器检查换段、换卡型、删段、换稿返回及先插入上方段落，确保位置始终明确，现有候选编辑不因切换而丢失。

## 任务 2 · 校验数据和卡片格式（高优先）

**文件**：`src/svg-cards.js`、`test/svg-cards.test.js`、`test/svg-cards-routes.test.js`。

1. 补回归用例：原文只有 `120`，柱状图填写 `20`，当前的 `sourceText.includes(number)` 会放行。按完整数值提取和比较，明确定义小数、千分位与百分号的规范化。第 2 列控制柱长，第 3 列可选显示文案，防止两列报出矛盾数值或语义。出现同值但指标关系无法自动判断时，在候选编辑区明确展示，交由作者核对。
2. 补概念卡包含 `! 关键差别` 的上游示例。当前 `withoutQuote` 仍把 `!` 行记作主内容，合法卡片会因核心行数超标被拒绝。主内容、可选重点、可选金句分别解析，和 vendor 顺序对齐。严格检查条目是字符串，避免对象或数字被隐式转成文字。
3. 对八种卡型核对可接受的行数、列数和可选行。将上游示例分别走「候选校验 → 单卡渲染 → 整篇渲染」，验证内容完整。继续使用原渲染器。执行 `node --test test/svg-cards.test.js test/svg-cards-routes.test.js`。

## 任务 3 · 统一配色和复制结果（中优先）

**文件**：`src/host.js`、`src/svg-cards.js`、`src/layout.js`、`client/svg-cards.jsx`、`client/state.js`。

1. 全文排版会合并全局设置和稿件偏好，单卡当前只读稿件偏好，并回退到硬编码配色。建立一个共用解析点，统一优先级并核对 Python 引擎的真实默认值。预览缓存键使用最终有效风格和配色。
2. 预览与复制复用同一个当前版本的结果。当前右栏复制每次重跑 Python，稿面冷复制也会先等待请求。慢请求后剪贴板授权可能失效。已有新鲜预览时直接在点击事件中复制；没有时先准备预览，完成后显示可点击的复制按钮。编辑、换稿或换主题后丢弃在途旧响应，防止重新写入过期结果。
3. 自动测试覆盖全局风格、稿件覆盖、无偏好三个用例，比较单卡和全文 SVG。浏览器验证冷启动复制、热复制、权限失败，以及延迟返回期间切换配色。复用现有富文本剪贴板接口。

## 任务 4 · 键盘与发布验收（中优先）

**文件**：`client/svg-cards.jsx`、`client/styles.css`、`README.md`，构建 `dist/client.js`。

1. 卡型弹窗的方向键现在每次从已选值计算下一项，连续按键会停在同一个选项。按当前焦点或独立游标计算，匹配实际列数，保留 Enter、空格确认以及 Escape 恢复焦点。测试连续三次方向键和窄窗单列。
2. 点击「插入正文」前显示目标与当前是否已预览，插入后提供一次明确的「定位到动画卡」，默认保持作者当前位置。用步骤卡、概念卡和手机演示卡确认稿面可播放、收起、重播，单卡和全文复制的剪贴板均含 SMIL。
3. 在公众号测试草稿里各粘贴一次单卡与整篇，分别检查动画、窄屏、卡片顺序和颜色。浏览器播放通过和公众号粘贴通过分别记录。执行 `npm test`、`npm run build`、`git diff --check`。建议按候选与校验、渲染与交互两次英文提交拆分。

实施顺序为任务 1、2，再做任务 3、4。
